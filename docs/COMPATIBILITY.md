# 兼容性与迁移政策

本文说明 FaceLink 当前承诺的兼容范围、版本协商方式和升级/降级边界。产品版本、
本地桥接协议版本和数据结构版本是三套独立编号，不能只看其中一个编号推断其余
部分一定兼容。

## 当前兼容基线

| 层级 | 当前写出版本 | 当前可读取/协商版本 | 说明 |
|---|---:|---:|---|
| FaceLink 产品 | `0.3.9`（最新已发布 Alpha） | 仅最新发布版获得安全修复 | `Unreleased` 中的功能尚不等于已发布承诺 |
| Blender 本地桥接协议 | `1.13` | `1.12`、`1.13` | 必须从双方明确列出的版本中选择，不按版本号范围猜测 |
| ShotSpec | `1.0` | `1.0` | 未知版本由严格模型校验拒绝 |
| Scene Snapshot | `1.4` | `1.0`—`1.4` | 老版本缺少的新能力不会被推断或补造 |
| Scene Patch | `1.4` | `1.0`—`1.4` | 老版本只可使用其原有能力；未知版本在 Blender 变更场景前被拒绝 |
| Retarget Profile | `1.0` | `1.0` | 映射始终需要人工复核 |
| 任务日志 | `1.0` | `1.0` | 未来版本不会被旧版自动降级或覆盖 |
| 修订审计条目 | `1.0` | `1.0`，并保留读取旧的无版本条目 | 审计元数据不是重启后可执行的回滚快照 |
| 安全诊断导出 | `1.0` | 仅作为支持报告写出 | 不是备份或恢复格式 |

Blender 扩展的最低声明版本是 Blender 4.2 LTS，主要验证版本是 4.5 LTS；测试矩阵
同时覆盖当前选定的 Blender 5.x 稳定版。5.x 属尽力兼容范围，不能据此承诺未来所有
Blender 5.x 小版本自动兼容。

## 桥接协议 1.13 如何协商

1. 当前发现记录继续使用 1.12 客户端可读取的原有字段集合，不加入协议字段；新客户端
   先调用 `GET /v1/health`。客户端也能读取将来显式带 `protocol_version` 的记录，但
   不能要求旧客户端理解新增发现字段。
2. `GET /v1/health` 是经过 Bearer Token 认证的版本无关启动入口。它不因请求中的
   协议版本不受支持而拒绝，响应体给出桥接端当前版本及
   `protocol_compatibility.supported_versions`。
3. 当前客户端和扩展都只明确支持 `1.12`、`1.13`，双方从交集中选择最高版本。
4. 除健康检查外，客户端通过 `FaceLink-Protocol-Version` 请求头发送选定版本。
   没有该请求头时仅按旧客户端 `1.12` 处理；这不是“自动采用最新版本”。
5. 格式错误的版本返回 HTTP 400 和 `invalid_protocol_version`；格式正确但不在明确
   支持列表中的版本返回 HTTP 426 和 `unsupported_protocol_version`。Python 客户端
   在发出任务请求前发现无交集时使用本地错误码 `invalid_protocol_version` 或
   `unsupported_protocol_version`。

`minor_versions_are_additive: true` 表示 1.13 相对 1.12 只增加能力，不表示任意未来
1.x 都可直接通信。FaceLink 始终使用显式版本白名单，避免把尚未理解的新语义误当成
兼容请求。

## 什么变化需要升版本

- 增加可忽略的响应字段、可选请求头、新端点或能力标记，可增加桥接协议次版本；
  服务器仍需明确列出实际支持的旧次版本。
- 删除字段、改变字段含义或类型、改变认证/提交/事务语义，必须增加桥接协议主版本。
- ShotSpec、Scene Snapshot、Scene Patch、任务日志、审计条目和诊断导出各自独立升
  数据结构版本。桥接协议升级不会自动迁移这些持久化或可交换数据。
- Python 主机的严格 JSON 模型不接受未声明字段。需要新增结构字段时，应先发布新
  结构版本和显式转换规则，不能依靠消费者“猜着忽略”。

## 数据迁移与失败策略

### Scene Snapshot、Scene Patch 与 ShotSpec

FaceLink 正常扫描和编译写出当前结构。旧 Scene Snapshot/Scene Patch 仍可进入已有的
兼容路径，但缺少指纹、导航、Rig 或烘焙守卫时只能使用旧版本实际表达的能力。
Scene Patch 的未知 `schema_version` 会以 `unsupported_schema_version` 拒绝，拒绝发生在
任何 Blender 场景变更之前。FaceLink 不静默删除新字段，也不把未来结构强制改写成旧
结构；应使用能读取源版本的 FaceLink 重新扫描、重新规划或执行有审计的显式转换。

### 任务日志

任务日志 `1.0` 使用同目录临时文件、刷盘和原子替换。语法损坏或结构不合法的日志会
被保留为 `.corrupt-<timestamp>`，新会话报告恢复异常。若日志使用格式合法但本版本
不支持的结构版本（包括未来版本或没有迁移器的旧版本），旧版会失败关闭：桥接不启动、
不把它当成损坏文件、不隔离、不覆盖原字节，也不自动重放其中任务。

遇到未来日志时，应停止反复尝试写入，先备份 `.blend` 和 FaceLink 状态目录，然后用
创建该日志的同版或更新版 FaceLink 完成检查与正常关闭。不要通过手工修改版本号来
绕过保护。

当前 Alpha 日志按规范化 `.blend` 路径确定工作区，但还没有跨 Blender 进程文件锁。
不要在两个 Blender 进程中同时为同一个已保存文件启动 FaceLink 桥接，否则两个会话
可能相互覆盖日志或把对方误判为异常退出；这项限制不影响不同 `.blend` 的并行实例。

### 修订审计与回滚

新写入审计条目带 `schema_version: "1.0"`；早期没有版本字段的字典条目仍可展示。
审计条目会保存在 `.blend` 中，并可能包含镜头标题、对象/Action 名称和警告，因此它
不是隐私脱敏格式。真正的回滚快照包含 Blender 运行时引用，只在当前会话内有效；重启
后审计历史仍可查看，但不能据此自动重放或伪造回滚。

## 升级与降级建议

1. 停止桥接并保存 `.blend`，备份 FaceLink 状态目录和要保留的产物。
2. Python 主机和 Blender 扩展尽量成对升级；启动后先运行 `facelink doctor`，确认
   健康检查中存在协议交集，再提交任务。
3. 升级后先扫描并暂存一个小补丁，人工检查后再应用；恢复报告从不自动重放任务。
4. 降级前确认旧版明确支持当前桥接和数据结构。若任务日志来自未来版本，使用匹配的
   新版处理，不要让旧版覆盖它。
5. Blender 原生对象、约束、Action、NLA 和关键帧仍是可编辑数据，但这不等于旧版
   FaceLink 能理解新版生成的全部审计或元数据。

安全边界及不承诺防护的本地攻击者见[威胁模型](THREAT_MODEL.md)，协议字段详见
[本地桥接协议](PROTOCOL.md)。
