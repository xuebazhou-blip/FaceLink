# Blender 任务与恢复中心

任务与恢复中心是 FaceLink v0.5.0 的第一个产品界面切片。它把本机桥接、任务队列和
上一次异常退出后的恢复状态集中显示在 Blender 的 **3D 视图 → 侧边栏 → FaceLink** 中。
本页描述当前开发分支的真实行为与限制；在路线图验收完成以前，它仍属于早期测试功能。

## 如何使用

1. 打开需要处理的 `.blend`，在 FaceLink 侧边栏点击 **Start Bridge**。
2. 在 **Tasks** 中查看排队数量、正在执行的任务、取消请求和最近结果。桥接运行或存在
   恢复提示时大约每 0.5 秒检查一次状态；离线空闲时退避到约 2 秒。
3. 对排队任务点击取消按钮并确认。运行中的任务也可以请求取消，但只会在安全检查点
   停止，限制见下文。
4. 如果顶部出现恢复提示，先检查场景和 **History**，按提示重新扫描，再点击
   **I Reviewed**。恢复状态没有确认以前，Blender UI 会禁用应用暂存、撤销和历史回滚；
   本机 HTTP 还会拒绝上述三类以及直接应用。

停止桥接时如果仍有活动任务，FaceLink 会先要求确认。手工刷新按钮只要求界面重绘，
不会重新排队任务，也不会访问模型提供商。

## 连接状态

| 界面状态 | 含义 | 用户操作 |
|---|---|---|
| 离线 | 当前 `.blend` 没有运行 FaceLink 桥接 | 点击 **Start Bridge** |
| 本机桥接已就绪 | 桥接已启动，没有活动任务或待恢复状态；**不表示 AI、Codex 账号或 API Key 已连接** | 可以从已经配置好的 MCP/CLI 发起安全工作流 |
| 正在工作 | 有排队或运行中的任务 | 在 **Tasks** 查看进度，必要时请求取消 |
| 需要恢复检查 | 上一次会话留下中断或未干净关闭记录 | 检查场景、历史并重新扫描，然后确认已检查 |
| 任务存储需要处理 | 任务日志当前不可用 | 检查 FaceLink 状态目录权限并重试 |
| 需要新版 FaceLink | 现有任务日志使用当前扩展不认识的未来版本 | 更新 FaceLink；原日志保持不变 |

运行时只显示经过格式验证的本机实例编号和桥接协议版本，不显示监听端口、状态文件路径
或桥接令牌。启动失败只显示稳定错误码和固定处理建议，不把底层异常原文放入面板。

## 任务列表与取消语义

任务中心显示队列容量、排队数量、正在运行数量、等待安全停止的数量、最多 6 个活动任务
和最近 3 个结束结果。更多活动任务只显示隐藏数量，避免异常输入让侧边栏无限增长。任务
条目只包含随机任务编号、允许列表中的任务类型、状态、检查点、队列位置和稳定错误码。

- **排队任务：** 取消会立即把任务变为已取消；任务不会开始执行，也不会修改 Blender
  场景。
- **运行任务：** FaceLink 不会向 Blender 注入异步异常。取消请求只能由执行器在明确的
  安全检查点处理；需要写场景的路径使用现有事务回滚机制。
- **完成与取消竞争：** 如果任务在取消请求生效以前已经安全完成，最终结果仍是完成，
  界面会说明“任务在取消生效前完成”，不会把成功结果伪装成已取消。
- **取消记录写入失败：** 当前会话中的取消状态不会为了写盘失败而撤销。排队任务已经从
  本次队列移除；运行任务仍只是等待安全检查点，甚至可能先完成。界面和 HTTP 会明确
  提示记录未保存并要求查看最终任务结果，不会声称运行任务已经停止。

### Blender 面板的真实限制

`bpy` 场景操作在 Blender 主线程同步执行。一个长任务占用主线程期间，Blender 界面可能
无法处理新的按钮点击，因此面板中的取消按钮目前只能可靠地取消仍在排队的任务。任务已经
运行时，可由独立 HTTP/MCP 客户端提交协作式取消请求；即使请求成功，也仍须等到下一个
安全检查点。没有安全检查点或已经完成的任务不能被强制终止。

这项限制意味着当前界面不是通用的“立即停止”按钮。未来若要改善运行中交互，需要把长
操作进一步拆成可让出主线程的有界步骤，同时保持 Blender 数据只能在主线程修改的约束。

## 恢复确认是什么

桥接协议 1.12 引入了持久任务日志能力；该日志是独立版本化的数据结构，当前
`schema_version` 为 `1.0`，不应与桥接协议 1.12/1.13 混为一谈。桥接启动时会识别
上一次会话中断的任务，并给出“重新扫描”或“检查修订历史”的指导。恢复确认只表示
用户已经检查提示：

- 不会重新排队或重放任何中断任务；
- 不会修改场景，也不会自动应用、撤销或回滚补丁；
- 不会把持久化审计记录当成可执行回滚快照；
- 如果确认状态无法安全写入任务日志，恢复提示保持未确认，用户可以修复存储问题后重试。

恢复要求存在期间，`apply_staged_patch`、`apply_patch`、`undo` 和
`rollback_revision` 四类高影响场景修改或回滚任务在进入队列以前返回 HTTP 409 /
`recovery_review_required`，因此不会创建任务记录。Blender 面板也禁用对应的应用、撤销
和回滚按钮。扫描场景、读取暂存/历史等检查操作仍可用；扫描可能补齐 FaceLink 稳定 ID
对象元数据，但不会应用动画或几何变更；暂存和丢弃预览也不会应用这些变更。确认成功后
高影响修改入口才恢复。

同一会话中仍可使用 FaceLink 的内存回滚快照；Blender 重启以后，应根据持久化审计记录
人工检查场景，而不是假定可以自动恢复到某个历史状态。

## 打开文件、首次保存和另存为

任务日志与当前工作区绑定。为避免新文件继续写入旧 `.blend` 的日志：

- 打开或切换 `.blend` 以前，FaceLink 会停止正在运行的桥接；文件加载后会清除临时暂存
  补丁和仅限当前会话的可执行回滚快照，并提示为新文件重新启动桥接。
- 未保存文件首次保存，或使用 **Save As** 改变文件路径后，如果工作区编号发生变化，
  FaceLink 会停止桥接并提示重新启动。
- 普通保存到同一路径不会因为这项规则停止桥接。

FaceLink 不会自动为新文件重启桥接。用户确认当前文件正确以后再手工启动，可以防止任务
误发到旧实例或旧工作区。

## 未知未来任务日志

如果旧版 FaceLink 遇到合法但更高的任务日志 `schema_version`，它会失败关闭：不启动
桥接、不隔离为损坏文件、不降级、不覆盖，也不自动重放。界面提示升级 FaceLink，并禁用
再次启动按钮，原始日志留给兼容版本处理。不要通过手工修改版本号来绕过检查。

格式本身损坏的日志与合法未来版本是两种不同情况；详细迁移规则见
[兼容性与迁移政策](COMPATIBILITY.md)。

## 安全与隐私边界

任务中心的自动刷新只读取只读状态模型，并且仅在模型发生变化时标记 Blender 3D 视图
重绘；离线且无需恢复时检查间隔退避到约 2 秒。读取不推进任务、不使排队任务超时、不写
任务日志，也不进行网络请求。任务中心的连接、任务和恢复状态模型经过固定允许列表和数量
限制，明确排除：

- 任务请求正文、ShotSpec、Scene Patch、场景快照和任务结果；
- `.blend`、状态目录及其他绝对路径；
- 场景、对象、骨骼和 Action 名称；
- 原始异常、提示词、Bearer Token、API Key 和私钥。

FaceLink 侧边栏的场景详情、暂存预览和修订历史本来就需要向当前 Blender 用户显示对象
名称或标题；这些区域不属于上述任务状态投影，也不应被当成可公开分享的脱敏诊断输出。

任务类型、时间关系、随机任务编号和活动数量仍可能暴露有限的工作模式；同一操作系统账户
下的恶意进程和任意 Blender Add-on 也不在 FaceLink 的隔离保证内。完整边界见
[FaceLink 威胁模型](THREAT_MODEL.md)。

## 本切片不包含什么

本切片只完成 Blender 内的桥接、任务和恢复界面，不包含：

- 在 FaceLink 界面中登录 Codex/ChatGPT 订阅；
- 读取、解析、复制或备份 Codex 的 `auth.json`；
- 在 Blender 中填写、测试或保存 API Key；
- 独立桌面应用、网页应用或云端桥接。

现有 MCP 客户端复用自身模型、以及 CLI 通过 `OPENAI_API_KEY` 使用 BYOK 的开发者流程
仍然可用。订阅与 API Key 双入口是 v0.5.0 的后续独立切片，不能把本任务中心宣传成已经
完成了账号接入。
